# ADR-002: Arquitectura del Frontend — SPA Basada en React, TypeScript y Vite

## Metadatos
- **Identificador**: ADR-002
- **Título**: Adopción de Single Page Application (SPA) con React, TypeScript y Vite para la Interfaz de Usuario
- **Estado**: APROBADO
- **Fecha de Aprobación**: 2026-10-01
- **Impacto en Baseline SRS / SAD de Análisis**: NINGUNO
- **Módulos Afectados**: MOD-01 a MOD-09 (Interfaz gráfica unificada para todos los casos de uso CU-01 a CU-30, CU-04.1)
- **Requisitos Trazados**: RF-01 a RF-18, RNF-04, RNF-05, RNF-06, RNF-07, RN-01 a RN-09

---

## 1. Contexto y Planteamiento del Problema
TraceFlow SCM es una plataforma de software orientada a la gestión rigurosa de configuración, proyectos, solicitudes de cambio (RFC), control de versiones, líneas base, pruebas y auditoría. Sus usuarios corresponden exclusivamente a los 7 actores canónicos autenticados:
1. Solicitante
2. Gestor de Configuración
3. Líder de CCB
4. Miembro de CCB
5. Desarrollador / Implementador
6. Asegurador de Calidad
7. Administrador de Seguridad

Los flujos de interacción requieren alta interactividad en pantalla: renderizado de árboles de configuración de ECS (MOD-03), matrices de trazabilidad, formularios dinámicos con clasificación de cambio Mayor/Menor (MOD-04), consolas de votación de CCB en tiempo real (CU-07), visualización de historiales y diffs de versiones (MOD-05), tableros de estado de QA y líneas base (MOD-06, MOD-07) y visores de auditoría inmutable (MOD-09).

El problema consiste en determinar la arquitectura del cliente frontend (interfaz de usuario) que proporcione la máxima fluidez, validaciones dinámicas y ergonomía (RNF-05), garantizando una experiencia de usuario rica sin introducir complejidad innecesaria de infraestructura de servidor frontend.

---

## 2. Criterios de Evaluación y Requisitos Relevantes
1. **Naturaleza del Sistema (Uso Interno Autenticado)**: TraceFlow SCM es un sistema transaccional de ingeniería cerrado. No requiere indexación por motores de búsqueda (SEO) ni acceso público anónimo.
2. **Interactividad y Experiencia de Usuario (RNF-05)**: Respuestas visuales instantáneas en validaciones de formulario, cambio dinámico de estado de RFC, y filtrado interactivo de auditoría e historial.
3. **Tipado Fuerte y Reducción de Errores en Tiempo de Compilación**: Capacidad de compartir contratos de datos tipados (DTOs) con los modelos de la API backend para eliminar discrepancias funcionales.
4. **Agilidad en el Desarrollo y Desempeño de Construcción**: Herramientas modernas de bundling con recarga rápida (Hot Module Replacement - HMR) y optimización estática eficiente.
5. **Neutralidad de Versión Mayor Inicial**: La decisión aprueba el paradigma y ecosistema tecnológico (React + TypeScript + Vite SPA). La versión mayor exacta (e.g. React 19 o React 18 LTS) se fijará y validará en la baseline de implementación técnica asegurando compatibilidad del ecosistema de dependencias.

## 3. Alternativas Consideradas

### Alternativa A: Frameworks con Server-Side Rendering (Next.js / Remix)
- **Descripción**: Renderizado híbrido en servidor utilizando Node.js como servidor de frontend antes de servir el HTML al cliente.
- **Ventajas**: Carga inicial ligeramente más rápida en dispositivos de baja potencia; excelente para SEO y sitios web públicos.
- **Desventajas**:
  - Sobrecosto operacional injustificado: requiere mantener y monitorear un servidor Node.js adicional dedicado exclusivamente a servir páginas de frontend.
  - SEO y web pública son totalmente irrelevantes para un sistema SCM corporativo de acceso estrictamente autenticado tras firewall/VPN (RNF-04).
  - Mayor complejidad en la gestión de sesiones, tokens de autenticación y manejo de cookies en dos capas de servidor (servidor frontend + servidor backend API).
- **Veredicto**: RECHAZADA.

### Alternativa B: Aplicación Web Tradicional Multi-Página (MPA con Plantillas SSR tipo Thymeleaf/EJS/Blade)
- **Descripción**: Páginas HTML generadas íntegramente por el backend por cada navegación.
- **Ventajas**: Arquitectura clásica muy conocida; sin lógica de cliente compleja.
- **Desventajas**:
  - Recarga completa de página en cada acción, produciendo parpadeo y degradación de la experiencia de usuario (contrario a RNF-05).
  - Dificultad para mantener componentes altamente interactivos como el árbol jerárquico de ECS, tableros de votación de CCB en tiempo real o diffs de versiones de archivos.
- **Veredicto**: RECHAZADA.

### Alternativa C: Single Page Application (SPA) con React, TypeScript y Vite — *SELECCIONADA*
- **Descripción**: Aplicación de página única construida como cliente enriquecido estático ejecutado en el navegador, desarrollada en TypeScript sobre React, empaquetada y servida eficientemente mediante Vite, que consume la API RESTful del backend mediante JSON.
- **Ventajas**:
  - Máxima fluidez interactiva: solo se intercambian datos ligeros JSON tras la carga inicial de los bundles estáticos.
  - Desacoplamiento total entre frontend y backend: los activos estáticos (HTML/JS/CSS) pueden ser servidos por cualquier servidor web ligero (Nginx/Caddy) o almacenamiento de archivos estáticos.
  - TypeScript proporciona tipado estricto en toda la capa de presentación, componentes, stores y contratos de API.
  - Vite ofrece tiempos de compilación y HMR instantáneos basados en esbuild y Rollup.
  - Enorme madurez del ecosistema de componentes UI accesibles (TailwindCSS, Radix/Shadcn, React Hook Form, TanStack Table/Query).
- **Desventajas**: Requiere control de tamaño de bundle inicial y adecuada gestión de estados en cliente.
- **Veredicto**: APROBADA.

## 4. Decisión Aprobada y Justificación Técnica
Se aprueba formalmente la adopción de una **Single Page Application (SPA)** basada en **React**, **TypeScript** y **Vite** para la interfaz de usuario de TraceFlow SCM.

### Justificación Técnica:
1. **Adecuación al Dominio**: Al ser una herramienta interna de ingeniería de software para 7 roles autorizados, el modelo SPA desacoplado es óptimo, eliminando la necesidad de servidores de renderizado intermedios.
2. **Garantía de Usabilidad y Rendimiento (RNF-05, RNF-06)**: La navegación sin recarga de página y la carga asíncrona de módulos por ruta (*code splitting*) ofrecen una experiencia fluida e inmediata para los operadores de cambio y miembros del CCB.
3. **Consistencia de Contratos de Datos**: El uso de TypeScript en cliente permite importar o generar interfaces idénticas a los DTOs definidos por la API backend (ADR-003, ADR-009), previniendo desincronizaciones de atributos en tiempo de compilación.
4. **Política de Versiones**: Se adopta React + TypeScript + Vite como estándar arquitectónico. La versión específica de React (18 LTS o 19 LTS) se ratificará formalmente en la baseline de implementación técnica en función de la estabilidad de las librerías satélite seleccionadas (componentes UI, enrutador y cliente HTTP).

---

## 5. Consecuencias y Trade-offs
### Positivas:
- Separación limpia de responsabilidades cliente/servidor.
- Despliegue de frontend como simples artefactos estáticos (HTML, JS, CSS) de alto rendimiento.
- Capacidad de ejecutar pruebas de componentes en aislamiento (Storybook / Vitest / React Testing Library).

### Negativas / Riesgos:
- La carga inicial de la aplicación transfiere bundles de JavaScript al navegador del cliente.
- La gestión de seguridad debe extremar precauciones contra Cross-Site Scripting (XSS) y no almacenar tokens sensibles en almacenamiento inseguro del cliente (ver ADR-006).

---

## 6. Mitigaciones y Medidas Compensatorias
1. **Optimización de Bundles**: Implementación de carga perezosa (*lazy loading*) y división de código por rutas (*code splitting*) mediante `React.lazy()` y dynamic imports de Vite.
2. **Seguridad y Almacenamiento Seguro**: El cliente frontend no manejará credenciales ni tokens en `localStorage`/`sessionStorage`; la autenticación se gestionará exclusivamente mediante cookies HttpOnly seguras (ADR-006).
3. **Manejo de Errores Global**: Configuración de Error Boundaries de React para capturar excepciones de interfaz de usuario sin degradar la sesión del operador.
